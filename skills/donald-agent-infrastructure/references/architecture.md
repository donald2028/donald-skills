# Project Agent Infrastructure

## Independent Layers

1. Canonical contract: `AGENTS.md`, with thin runtime adapters.
2. One canonical Skill source and one layout.
3. Optional entry routing.
4. Optional governance.
5. Optional Claude/Codex/CodeBuddy subagent registry.

Runtime installation and distribution are separate operations, not another authoring layer.

## Skill Source

Ordinary projects use an unregistered authoring tree:

```text
skills/<skill>/SKILL.md
skills/<category>/<skill>/SKILL.md
```

Do not link or copy this tree into runtime discovery paths. This prevents work-in-progress edits
from changing unrelated repository sessions.

If the user explicitly chooses a runtime-native repo Skill, place the only source directly in that
runtime's directory, such as `.claude/skills/`, `.agents/skills/`, or `.codebuddy/skills/`. Do not
also keep root `skills/` or other runtime copies.

Use a flat layout by default. Categorize only for genuine Skill families. Names are globally unique,
directories are kebab-case, and each Skill is self-contained. Mixed or deeper layouts are invalid
for new scaffolds and exist only as migration observations.

## Optional Entry And Governance

Add one `enter-project` Skill only when requests need capability discovery, mode selection, or
cross-Skill routing. Add governance only when the project needs local review and structural audit.
Their locations follow the selected source and layout:

```text
flat:         <source>/enter-project/
              <source>/review-skill-best-practices/
categorized:  <source>/application/enter-project/
              <source>/development/review-skill-best-practices/
```

The entry routes to the narrowest Skill; it is not a workflow engine. The audit checks structure;
it does not make semantic decisions or install Skills.

## Runtime Boundary

Only create runtime Skill state for an explicit request and named consumer. Prefer the runtime's
supported plugin, extension, or installer. Installed state is not the authoring source and must not
be regenerated by normal editing.

Never ship a generic project helper that maps one source into `.agents/skills/`,
`.claude/skills/`, `.codebuddy/skills/`, and `.workbuddy/skills/`. Live junctions and symlinks expose
unfinished edits immediately. See `migration.md` for removing older generated mirrors.

## Subagents

Enable subagents only for recurring isolated roles. The initializer creates:

```text
agents/registry.yaml
agents/sync_agents.py
```

The registry owns metadata and runtime wiring; the owning Skill's `references/*-agent.md` or
`references/*-prompt.md` owns behavior. Generated output is limited to:

```text
.claude/agents/<id>.md
.codex/agents/<id>.toml
.codebuddy/agents/<id>.md
agents/INDEX.md
```

The generator removes only files carrying its generated notice and preserves unknown files.
WorkBuddy Skill compatibility does not establish a WorkBuddy subagent format.

WorkBuddy uses `.codebuddy/skills/` in the measured build and does not discover
`.workbuddy/skills/`. Select `.codebuddy/skills/` only when a CodeBuddy/WorkBuddy-native source is
explicitly requested. Marketplace Skills, Experts, and Expert Teams remain product-level installs.

## Red Lines

- Do not treat authoring source as installed runtime state.
- Do not maintain multiple canonical Skill trees or live mirrors.
- Do not duplicate shared rules across runtime adapters.
- Do not invent discovery paths or subagent formats without measuring the runtime.
