# Output Contract

## Planning Result

Report:

- current and target Skill layout;
- selected canonical Skill source and whether it is unregistered authoring or explicitly runtime-native;
- independent Entry, Governance, and Subagent decisions;
- canonical versus installed or generated ownership;
- non-destructive migration risks when the repository already exists;
- exact verification that will prove each enabled layer.

Do not use cumulative profile names to describe the target architecture.

## Implemented Result

Report:

- canonical files and generated tooling changed;
- selected source, layout, and enabled optional layers;
- legacy mirror cleanup and any preserved conflicts;
- Skill audit summary, including dependencies and structural issues;
- Claude/Codex/CodeBuddy Subagent registry/generator result when enabled;
- configured runtime discovery versus live runtime checks actually performed;
- skipped checks and their reason.

Do not call the infrastructure ready until relevant authoring isolation, audit, migration, and
Subagent checks pass or are explicitly reported as unavailable.
