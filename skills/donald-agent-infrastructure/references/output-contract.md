# Output Contract

## Planning Result

Report:

- current and target Skill layout;
- independent Entry, Governance, and Subagent decisions;
- canonical versus generated ownership;
- non-destructive migration risks when the repository already exists;
- exact verification that will prove each enabled layer.

Do not use cumulative profile names to describe the target architecture.

## Implemented Result

Report:

- canonical files and generated tooling changed;
- selected layout and enabled optional layers;
- runtime mirror modes and sync/check results;
- Skill audit summary, including dependencies and mirror state;
- Claude/Codex/CodeBuddy Subagent registry/generator result when enabled;
- configured runtime discovery versus live runtime checks actually performed;
- skipped checks and their reason.

Do not call the infrastructure ready until relevant audit, mirror, and Subagent checks pass or are
explicitly reported as unavailable.
